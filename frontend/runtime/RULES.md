# 前端全局规则

## 1. 总体规则

1. 所有前端代码只能放在 `frontend/` 目录下。
2. 不允许把 Vue 页面、静态资源、前端配置文件放入后端目录。
3. 前端新增内容不得破坏现有后端工程结构。
4. 所有前端开发工作必须遵循任务驱动方式推进。

## 2. 代码规范

1. 组件必须保持可读、可拆分、可复用。
2. 避免单个组件过大、职责过多。
3. 文件名、变量名、方法名、组件名应清晰可理解。
4. 无用代码、废弃注释、无用导入要及时清理。
5. 业务逻辑尽量不要堆积在页面展示组件中。

## 3. 目录规范

推荐在 `frontend/app/src/` 下使用以下目录：

- `api/`：按业务划分接口请求封装
- `components/`：可复用公共组件
- `layouts/`：布局组件
- `views/`：页面级视图
- `router/`：路由配置
- `stores/`：Pinia 状态管理
- `utils/`：通用工具函数
- `styles/`：全局样式与主题样式

## 4. 组件规范

1. 页面级组件放在 `views/`。
2. 可复用组件放在 `components/`。
3. 布局壳子放在 `layouts/`。
4. 每个组件应尽量只承担单一明确职责。
5. `props`、事件、暴露能力应保持清晰可预期。

## 5. 接口调用规范

1. 所有 HTTP 请求统一封装在 `api/` 目录下。
2. 不允许在各页面中到处直接写 Axios 请求。
3. baseURL、超时、拦截器、统一错误处理必须集中管理。
4. 接口方法命名要体现业务语义，不使用临时命名。
5. 接口字段使用必须严格以后台 API 文档为准。

## 6. 状态管理规范

1. 跨页面共享状态使用 Pinia 管理。
2. 仅当前组件临时使用的状态保留在组件内部。
3. 不要把所有变量都放入全局状态。
4. 登录态、用户信息、关键全局状态可以集中管理。

## 7. 路由规范

1. 路由必须集中定义和维护。
2. 路由命名应稳定、清晰、可读。
3. 访问控制逻辑必须统一处理。
4. 需要登录才能访问的页面，不允许依赖零散判断。

## 8. UI 规范

1. Element Plus 作为主 UI 组件库。
2. 所有页面保持统一的视觉与交互风格。
3. 相似操作不允许出现混乱交互模式。
4. 表单、表格、弹窗、消息提示应保持统一使用方式。

## 9. 文档规范

1. 前端任务推进状态必须同步更新到 `frontend/runtime/STATE.md`。
2. 重要阶段成果应记录到 `frontend/docs/`。
3. 阶段归档、决策记录、历史输出应放到 `frontend/archive/`。

## 10. 协作规范

1. 前端联调必须以后台 API 文档为唯一接口依据。
2. 接口定义不清楚时，不允许猜测实现。
3. 发现接口不一致时，先记录问题，再决定是否调整实现。

## 11. 页面产出规范引用

前端页面、组件、布局、交互开发时，除遵循本文件外，还必须同时遵循以下文档：

- `frontend/docs/UI_STYLE_GUIDE.md`
- `frontend/docs/PAGE_SKELETON_GUIDE.md`
- `frontend/docs/COMPONENT_GUIDE.md`

具体要求如下：

1. 所有页面必须符合项目 UI 风格约束，禁止生成营销页风格、强渐变风格、展示模板风格页面。
2. 所有页面必须优先按真实业务系统骨架组织信息，不允许用通用演示模板替代业务页面结构。
3. 所有按钮、表单、表格、弹窗、状态提示等组件交互应保持统一，不允许每个页面形成独立视觉规则。
4. 如遇到新页面设计决策不明确，优先回到上述规范文档判断，而不是自由发挥。
