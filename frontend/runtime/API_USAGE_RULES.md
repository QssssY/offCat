# 前端接口使用规则

## 1. 接口依据来源

前端联调时，必须以后台 API 文档作为主要依据。

主要参考位置：

- 根目录下的 `docs/`
- 其中与 API 相关的后端接口文档

## 2. 明确禁止事项

前端开发过程中，不允许出现以下行为：

- 自行发明接口地址
- 自行发明请求参数
- 自行发明返回字段
- 在联调代码中私自重命名后台字段并掩盖问题
- 跳过文档、凭经验直接接接口

## 3. 正确联调流程

每个接口都应按以下顺序接入：

1. 先阅读后台 API 文档
2. 确认请求方法、接口路径、参数定义、请求体、响应结构
3. 在 `frontend/app/src/api/` 中编写接口封装
4. 再由页面或 store 调用接口封装
5. 根据真实响应结果校验页面展示字段

## 4. 不一致处理规则

如果出现以下任一不一致：

- 文档与后台实际返回不一致
- 后台实际返回与前端预期展示不一致
- 文档描述不完整导致无法安全联调

则前端应执行以下动作：

1. 明确记录问题
2. 停止基于猜测继续扩展
3. 等待确认或修正文档
4. 在确认后再更新实现

## 5. 命名规则

1. 接口封装方法名必须体现业务语义。
2. 同一业务域的接口尽量收敛在同一模块中。
3. 不使用 `getData`、`postInfo`、`testRequest` 这类含义模糊的命名。

## 6. 响应处理规则

1. 能统一处理的响应逻辑尽量集中处理。
2. 错误处理方式应保持一致。
3. 登录失效、权限不足等情况应统一处理。
4. 面向用户的错误提示不应直接暴露后台内部细节。

## 7. 变更控制

如果后台接口发生变化，应按以下顺序处理：

1. 先更新后台接口文档
2. 再更新前端接口封装
3. 最后更新页面或状态调用逻辑

不允许基于未文档化的接口变化，直接修改页面逻辑。
