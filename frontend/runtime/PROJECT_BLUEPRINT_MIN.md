# 前端项目最小蓝图

## 1. 项目定位

本目录是当前项目的独立前端工作区。

现有后端工程已经存在并处于可运行状态。
前端从零开始创建，统一放在 `frontend/` 目录下，不改动现有后端结构。

前后端职责分离如下：

- 后端：负责业务逻辑、认证、额度、简历流程、面试流程、管理端接口等
- 前端：负责页面展示、交互流程、表单处理、状态呈现、接口联调等

## 2. 前端目标

基于现有后端 API，建设一个独立的前端应用，用于承载用户端与管理端页面能力。

前端建设目标：

- 保持模块边界清晰
- 保持界面与代码风格统一
- 严格基于后端 API 文档联调
- 支持按任务顺序逐步推进开发

## 3. 技术栈

当前前端技术栈固定为：

- Vue 3
- Vite
- Element Plus
- Vue Router
- Pinia
- Axios

## 4. 工程结构约定

`frontend/app/` 用于承载真实前端代码工程。

建议内部结构如下：

- src/
  - api/
  - assets/
  - components/
  - layouts/
  - router/
  - stores/
  - styles/
  - utils/
  - views/

## 5. 模块推进顺序

建议按以下顺序推进：

1. 前端工程初始化
2. 基础布局与路由搭建
3. 登录与认证相关页面
4. 用户侧核心业务页面
5. 管理侧页面
6. 联调修正与交付收口

## 6. 接口联调原则

前端必须严格依据后端 API 文档进行联调。

不允许自行猜测接口地址、请求字段、响应结构。
如果后端文档与实际行为不一致，应先记录问题，再进行确认和修正，不允许前端擅自假设。

## 7. 开发原则

- 前端必须保持独立，不混入后端代码目录
- 不允许将前端代码写入 `server/`
- 不因前端需求去改造后端控制结构
- 前端开发进度统一记录在 `frontend/runtime/` 和 `frontend/tasks/` 下

## 8. 界面产出原则

前端界面建设必须以“真实业务系统”作为目标，而不是展示型页面。

界面产出要求如下：

- 风格上保持专业、克制、清晰、工具化
- 页面结构优先体现业务信息层级与操作效率
- 不使用大面积渐变、玻璃拟态、营销横幅、模板化卡片堆叠等强 AI 风格表达
- 所有页面、布局、组件产出需同时遵循以下文档：
  - `frontend/docs/UI_STYLE_GUIDE.md`
  - `frontend/docs/PAGE_SKELETON_GUIDE.md`
  - `frontend/docs/COMPONENT_GUIDE.md`
