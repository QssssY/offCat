# TASK 06D - 简历诊断 taskId 传递一致性修复

## 1. 任务目标

修复当前前端在简历上传成功后没有使用真实返回 taskId 进行结果页跳转与详情查询的问题，确保上传接口返回的 taskId 在上传页、结果页、任务详情请求三处保持完全一致。

---

## 2. 问题背景

当前后端链路已验证一致：

- 上传接口返回：
  - `data: 2039737155583942658`
- 后端异步处理成功日志：
  - `taskId: 2039737155583942658`

说明后端上传返回值与真实任务链路使用的 taskId 已一致。

但当前前端后续请求任务详情时，请求的却是另一个 taskId，例如：

- `2039737155583942700`

这说明当前问题不在后端，而在前端 taskId 传递链路中出现了错误。

当前必须修复：

- 上传成功后的 taskId 提取
- 上传页到结果页的 taskId 传递
- 结果页发起任务详情请求时使用的 taskId 来源

确保三处始终使用同一个真实值。

---

## 3. 本任务范围

本任务应完成以下内容：

1. 检查上传成功后前端如何读取 taskId
2. 检查上传页如何把 taskId 传入结果页
3. 检查结果页如何读取 taskId
4. 检查结果页请求任务详情接口时使用的 taskId 来源
5. 移除错误 taskId 来源、旧逻辑、mock 残留或错误变量引用
6. 修复 taskId 全链路传递一致性
7. 更新前端状态记录

---

## 4. 本任务不包含内容

本任务不包含以下内容：

- 修改后端上传接口
- 修改后端任务详情接口
- 重构结果页整体样式
- 开发历史记录页
- 修改无关业务模块

---

## 5. 必须排查的重点

### 5.1 上传成功后的 taskId 提取

必须明确：

- 当前上传成功后前端读取的是哪个字段
- 真实上传响应中的 taskId 字段路径是什么
- 当前是否错误读取了其他字段

### 5.2 跳转参数来源

必须明确：

- `router.push` 使用的 taskId 来自哪里
- 是否存在本地生成值、旧变量、mock 变量、错误字段
- 跳转 URL 中的 taskId 是否与上传返回值完全一致

### 5.3 结果页参数读取

必须明确：

- 结果页当前使用 `route.params.taskId` 还是其他来源
- 是否存在 query / state / 本地变量覆盖路由参数的情况
- 是否因为类型转换或字段名错误导致 taskId 改变

### 5.4 任务详情请求参数来源

必须明确：

- `/task/{taskId}` 的 taskId 究竟来自哪里
- 是否与路由参数一致
- 是否使用了错误的默认值、旧值或其他来源

---

## 6. 修复原则

1. 上传接口真实返回的 taskId 必须作为全链路唯一可信来源。
2. 上传页、结果页、任务详情请求三处必须使用同一个 taskId。
3. 不允许保留 mock、开发模式临时变量、时间戳生成等逻辑。
4. 修复应以最小改动为原则。
5. 不修改后端文件。

---

## 7. 正确行为要求

修复后应满足以下行为：

1. 上传接口返回 `data = X`
2. 上传页使用 `X` 进行跳转
3. 结果页从路由中读取到的也是 `X`
4. 结果页请求 `/task/X`
5. 后端能正常返回任务详情，不再出现“任务不存在”
