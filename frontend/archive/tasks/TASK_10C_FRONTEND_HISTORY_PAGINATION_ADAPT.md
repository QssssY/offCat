### TASK_10C_FRONTEND_HISTORY_PAGINATION_ADAPT

**目标：​**  
根据后端最新分页默认值调整前端历史记录页面，使前端正确传递和管理分页参数，并适配后端分页返回结构。

**后端最新约定：​**
- 模拟面试历史：
  - 默认 `pageNum = 1`
  - 默认 `pageSize = 5`
- 简历诊断历史：
  - 默认 `pageNum = 1`
  - 默认 `pageSize = 10`

**前端适配目标：​**
1. 面试历史页面请求接口时，默认按 `pageSize = 5` 发起请求
2. 简历诊断历史页面请求接口时，默认按 `pageSize = 10` 发起请求
3. 翻页时正确传递 `pageNum` 和 `pageSize`
4. 正确解析后端分页返回：
   - `list`
   - `pageNum`
   - `pageSize`
   - `total`
   - `totalPages`
   - `hasNextPage`
   - `hasPreviousPage`
5. 前端列表渲染必须基于真实数组字段，不再把整个响应对象直接当数组
6. 如果页面已有分页组件，则同步绑定分页状态
7. 如果页面还没有分页交互，则至少补上“上一页 / 下一页”能力

**修改范围建议：​**
- 面试历史相关页面
  - `HomeView.vue`
  - `InterviewHistoryView.vue`
- 简历诊断历史相关页面
  - 对应的历史页面/组件
- 如有统一 API 封装，也检查其分页参数处理逻辑

**要求：​**
1. 不修改后端接口协议
2. 不引入 interviewMode 等已回退需求
3. 只围绕当前历史分页适配做前端修改
4. 排序前必须确保拿到的是数组，避免再次出现：
   - `sort is not a function`
5. 保持空数据、末页、无上一页/下一页等场景下的 UI 稳定

**输出要求：​**
1. 修改原因说明
2. 修改文件清单
3. 面试历史分页适配代码
4. 简历诊断历史分页适配代码
5. 如何验证：
   - 面试历史默认 5 条
   - 简历诊断历史默认 10 条
   - 翻页正常
   - 空数据不报错
