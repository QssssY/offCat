# TASK 04 - 认证页面重构与登录注册双接口联调

## 1. 任务目标

在现有登录功能基础上，重构认证页面的视觉样式与布局结构，使其接近目标参考图中的左右分栏样式，并接入登录与注册两个真实接口。

本任务的核心目标是：

- 将认证页面升级为统一的双态页面
- 支持登录与注册两种真实业务流程
- 保持页面风格专业、克制、统一
- 接入左侧品牌主视觉图片 `logo.jpg`
- 不破坏现有登录态、token、路由守卫、请求拦截逻辑

---

## 2. 任务背景

当前前端登录功能已经完成，且登录接口已接通。
当前希望将认证页面重构为参考图片中的左右分栏样式。

已知条件如下：

- 当前登录功能可用
- 后端也已提供注册接口
- 前端认证页面视觉效果尚未达到目标样式
- 本地已有左侧品牌图片资源 `logo.jpg`
- 页面需要同时满足视觉升级与真实接口联调要求

---

## 3. 本任务范围

本任务应完成以下内容：

1. 将当前认证页面重构为左右分栏布局
2. 左侧构建品牌展示区
3. 接入本地 `logo.jpg` 作为品牌主视觉
4. 右侧构建认证表单区
5. 支持登录态与注册态切换
6. 登录态接入真实登录接口
7. 注册态接入真实注册接口
8. 注册表单字段、提交逻辑、返回处理必须遵循后端接口文档
9. 保持现有 token 管理、请求拦截器、路由守卫逻辑可用
10. 注册成功后提供合理流转逻辑
11. 更新 `frontend/runtime/STATE.md`

---

## 4. 本任务不包含内容

本任务不包含以下内容：

- 找回密码
- 第三方登录
- 手机验证码登录
- 复杂 RBAC 权限系统
- 按钮级权限控制
- 管理端认证逻辑
- 复杂动画系统

---

## 5. 页面结构要求

### 5.1 左侧品牌展示区

左侧应包含：

- 品牌标签或小标题
- 系统主标题
- 一段简短业务说明
- 主视觉图（使用 `logo.jpg`）
- 轻量背景装饰

文案必须符合当前项目业务语义，不得照搬参考图原文。

建议业务表达方向：

- 智能模拟面试与简历诊断系统
- 聚焦简历评估、模拟面试与历史记录管理
- 帮助用户更高效地完成求职准备

### 5.2 右侧认证表单区

右侧应包含：

- 页面主标题
- 副标题
- 登录 / 注册模式切换
- 表单区
- 主按钮
- 底部辅助切换说明

---

## 6. 登录态要求

登录态必须继续使用真实接口联调。

要求如下：

1. 登录字段严格遵循后端 API 文档
2. 登录成功后继续使用现有 token 保存逻辑
3. 登录成功后按现有路由逻辑返回目标页面或进入系统首页
4. 不允许为了重构页面而破坏现有登录流程

---

## 7. 注册态要求

注册态必须接入真实注册接口。

要求如下：

1. 注册字段严格依据后端 API 文档
2. 不允许猜测字段名或响应结构
3. 表单应包含必要的前端校验
4. 提交中状态应清晰可见
5. 注册成功后应提供合理的后续流转

推荐流转方式二选一：

### 方案 A：注册成功后跳转登录态
- 提示注册成功
- 自动切换到登录模式
- 可自动回填用户名

### 方案 B：注册成功后自动登录
- 若后端接口直接返回可用登录态信息，可按真实接口能力处理

如后端文档无明确支持，优先使用方案 A。

---

## 8. 资源接入要求

本任务必须接入项目中的 `logo.jpg`。

推荐资源位置：

- `frontend/app/src/assets/logo.jpg`

若当前资源位置不规范，可在不破坏前端工程规范的前提下整理到 `src/assets/`。

---

## 9. 接口开发要求

本任务必须以真实后端接口为准。

要求如下：

1. 登录接口与注册接口统一在 `src/api/` 下封装
2. 不允许在页面中散落裸请求
3. 所有字段命名、响应处理、token 提取方式都必须以后端 API 文档为准
4. 如文档存在歧义，应集中在接口层做清晰收敛，不得在页面层扩散不确定逻辑
5. 如注册与登录接口返回结构不同，应分别处理，不得强行混用

---

## 10. 风格要求

本页面需参考目标图的左右分栏结构与视觉方向，但必须进行业务适配。

具体要求：

- 页面整体清晰、稳定、轻柔
- 左侧强调品牌与系统定位
- 右侧强调操作与表单输入
- 文案应专业真实，不空泛
- 不允许与当前项目无关的心理陪伴类表达
- 不允许过度堆砌装饰元素
- 不允许为了视觉模仿而损害业务可用性
