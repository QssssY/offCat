# TASK 06A - 简历上传与结果页流转修复

## 1. 任务目标

修复当前简历诊断上传页在上传成功后未正确跳转到结果页的问题，确保上传页只负责发起任务，结果页负责承接任务状态展示，从而避免页面卡在上传页、用户误判流程状态并重复提交消耗额度。

---

## 2. 问题背景

当前前端已开始开发简历诊断结果页，但实际测试中发现以下问题：

1. 用户上传 PDF 后，页面仍停留在上传页
2. 上传按钮持续显示“处理中”
3. 前端没有正确进入结果页承接逻辑
4. 用户为了确认结果，可能重复上传，导致额度被继续消耗
5. 即使继续让代码助手执行，问题本身也未真正修复

当前后端情况已知如下：

- 上传接口已可成功创建任务
- 后端异步处理链路可正常执行
- 后端已有任务详情接口 `/task/{taskId}`
- 当前问题重点不在后端，而在前端上传成功后的状态收口与跳转逻辑

---

## 3. 本任务范围

本任务应完成以下内容：

1. 检查上传接口真实返回结构
2. 确认前端是否正确读取 `taskId`
3. 修复上传成功后跳转结果页逻辑
4. 修复上传页 loading 状态未正确结束的问题
5. 明确上传页与结果页的职责边界
6. 降低重复上传导致额度浪费的风险
7. 更新前端状态记录

---

## 4. 本任务不包含内容

本任务不包含以下内容：

- 修改后端上传接口
- 扩展历史记录页
- 开发复杂结果分析图表
- 修改 RabbitMQ 逻辑
- 重做首页或认证页

---

## 5. 问题判断重点

### 5.1 上传成功后的返回结构

必须明确：

- 上传成功后后端返回的字段结构是什么
- `taskId` 在哪个字段路径下
- 当前前端是否读错字段或根本未读取到 `taskId`

不允许猜字段。

### 5.2 路由跳转逻辑

必须检查：

- 上传成功后是否执行结果页跳转
- `router.push` 是否实际被调用
- 跳转路径是否正确
- `taskId` 是否正确拼入路由参数

### 5.3 loading 状态修复

必须检查：

- 上传按钮 loading 是否只用于上传请求阶段
- 请求结束后是否正确关闭
- 是否因为异常分支、成功分支或跳转逻辑缺失导致按钮一直卡在处理中

### 5.4 重复提交防护

本任务应尽量降低以下风险：

- 用户因为停留在上传页误以为未成功
- 于是重复提交
- 导致额度重复扣减

至少应通过更清晰的状态收口与成功后跳转，减少重复操作概率。

---

## 6. 正确业务流要求

修复后应满足以下流转：

1. 用户在上传页选择 PDF
2. 点击提交
3. 上传按钮进入提交中状态
4. 上传接口返回成功结果
5. 前端正确读取 `taskId`
6. 上传页结束 loading
7. 前端自动跳转到结果页
8. 结果页根据 `taskId` 查询任务状态
9. 结果页展示处理中 / 已完成 / 已失败状态

---

## 7. 技术要求

1. 接口请求统一放在 `src/api/`
2. 不允许在页面中散落不稳定的临时逻辑
3. 路由结构必须清晰
4. 上传页不承担长期轮询职责
5. 结果页承担任务状态承接职责
6. 使用 JavaScript，不切换 TypeScript

3. 上传按钮不会无限停留在“处理中”

5. 结果页可承接任务状态展示
6. 用户不再需要通过重复上传确认流程是否成功
