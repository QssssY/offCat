# TASK 03 - 用户登录与前端鉴权接入

## 1. 任务目标

在现有前端工程基础上，完成用户登录页、登录态管理、token 注入、路由守卫等最小可用鉴权闭环。

本任务的核心目标不是做复杂权限系统，而是为后续真实业务接口联调提供必要前置条件。

---

## 2. 任务背景

当前前端已经完成基础工程初始化，并已开发“简历诊断入口页”作为第一个真实业务页面。

在尝试与后端真实接口联调时，发现简历上传请求返回 403。
已确认当前前端尚未实现登录模块，处于未登录状态，也没有 token。

因此，当前问题本质为：

- 后端业务接口依赖用户身份
- 前端尚未建立登录与鉴权能力
- 业务页面虽然已具备结构，但缺少真实访问前提

本任务用于补齐这一前置能力。

---

## 3. 本任务范围

本任务应完成以下内容：

1. 创建用户登录页
2. 接入登录接口封装
3. 建立 token 存储机制
4. 在请求层自动注入 token
5. 建立最小路由守卫能力
6. 未登录访问受保护页面时，自动跳转登录页
7. 登录成功后可返回原目标页面
8. 对现有业务页面增加未登录保护
9. 更新前端状态记录

---

## 4. 本任务不包含内容

本任务暂不包含以下内容：

- 注册功能
- 找回密码
- 第三方登录
- 多角色复杂权限系统
- 管理端权限系统
- 细粒度按钮级权限控制
- 登录后用户资料完整中心页

---

## 5. 设计目标

本任务应实现“最小可用登录闭环”，要求如下：

- 登录流程清晰
- 登录态可持续保存
- 页面跳转逻辑清晰
- 与现有前端结构兼容
- 与后续真实接口联调顺畅衔接

页面与交互风格应继续保持：

- 专业
- 克制
- 清晰
- 真实业务系统风格

不允许做成营销页、演示页、炫技页。

---

## 6. 页面与逻辑要求

### 6.1 登录页要求

登录页应至少包含：

- 页面标题
- 简要说明
- 用户登录表单
- 必填校验
- 提交按钮
- 登录中状态
- 登录失败提示

登录页文案应真实、简洁，不使用空泛宣传文案。

### 6.2 登录接口接入要求

应在 `src/api/` 下建立登录相关接口封装。

接口接入应遵循：

- 统一请求实例
- 统一错误处理
- 不在页面中散落裸请求

如后端接口文档已明确，应以文档为准；
如暂时无法确认完整接口字段，可使用清晰占位结构，但不能写成混乱临时代码。

### 6.3 token 管理要求

应建立最小 token 管理机制，包括：

- 登录成功后保存 token
- 页面刷新后仍可读取 token
- 提供获取 token、设置 token、清除 token 的统一方法
- 不允许在多个页面手写重复 token 逻辑

### 6.4 请求拦截要求

应在请求层完成 token 自动注入能力：

- 若存在 token，则自动加入请求头
- 请求头格式应遵循后端要求
- 若后端要求 `Authorization: Bearer xxx`，则按该格式处理
- 若后端要求其他格式，则以接口文档为准

### 6.5 路由守卫要求

应建立最小路由守卫逻辑：

- 对需要登录访问的页面进行保护
- 未登录访问时，跳转到登录页
- 跳转时保留原始目标路径
- 登录成功后自动返回原目标页面
- 首页是否强制登录，可根据当前产品策略决定，但业务页应支持受保护访问

### 6.6 已有页面联动要求

应对已有“简历诊断入口页”做最小联动调整：

- 未登录时，不直接发起真实上传请求
- 应提示用户先登录
- 应支持跳转到登录页
- 登录后可继续进入业务页
