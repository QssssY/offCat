# TASK 07 - 简历诊断结果页结构化展示

## 1. 任务目标

将当前简历诊断结果页中直接输出原始 JSON / 对象字符串的展示方式，改造为结构化、可读性强、符合真实业务系统风格的结果展示页面。

---

## 2. 任务背景

当前前端已经打通以下链路：

- 简历上传
- 任务创建
- 跳转结果页
- 任务状态查询
- 结果获取

当前问题在于：

- 结果页已拿到后端返回的诊断结果
- 但结果内容仍以原始对象/JSON 字符串形式直接展示
- 页面缺乏结构化信息分层
- 用户难以快速理解结果重点

这说明当前链路已通，下一步重点应从“功能是否通”转为“结果展示是否可用”。

---

## 3. 本任务范围

本任务应完成以下内容：

1. 分析当前后端返回的简历诊断结果结构
2. 基于真实返回字段进行结构化展示
3. 将原始对象输出改为模块化结果展示
4. 提升结果页的可读性、层级感和产品感
5. 保持页面风格与现有系统一致
6. 更新前端状态记录

---

## 4. 本任务不包含内容

本任务不包含：

- 修改后端结果生成逻辑
- 增加新的诊断字段
- 重构上传链路
- 开发历史记录页
- 增加导出 PDF 等高级功能

---

## 5. 展示设计要求

### 5.1 页面展示原则

结果页应遵循以下原则：

1. 摘要优先
2. 重点优先
3. 信息分组清晰
4. 先让用户快速理解结论，再展示细节

### 5.2 推荐展示结构

建议结果页至少拆分为以下模块：

#### 模块一：总体评价
用于展示：

- 综合分数
- 综合等级
- 总体结论 / 总体评价

#### 模块二：亮点概览
用于展示：

- 当前简历中的主要优点
- 可保留或重点强化的信息

#### 模块三：技能情况
用于展示：

- 技能得分
- 技能列表
- 当前技术栈情况
- 技能描述建议

#### 模块四：基础信息完整度
用于展示：

- 姓名
- 邮箱
- 电话
- GitHub
- 博客
- 基础信息完整性评价

#### 模块五：工作与项目经验
用于展示：

- 工作经验得分
- 项目经验得分
- 经验描述问题
- 可优化方向

#### 模块六：优化建议
用于展示：

- 主要改进建议
- 可执行修改方向

---

## 6. 字段使用要求

必须严格依据后端当前真实返回字段进行渲染。

不允许：

- 自行发明字段
- 擅自重命名后端字段并掩盖问题
- 因为字段复杂而直接继续输出整段 JSON

如果后端返回字段中某些内容是嵌套结构，应在前端进行合理拆解和格式化展示。

---

## 7. UI 要求

本任务必须遵循以下规范：

- `frontend/runtime/RULES.md`
- `frontend/runtime/API_USAGE_RULES.md`
- `frontend/docs/UI_STYLE_GUIDE.md`
- `frontend/docs/PAGE_SKELETON_GUIDE.md`
- `frontend/docs/COMPONENT_GUIDE.md`

页面风格要求如下：

- 专业、克制、清晰
- 不做花哨图表
- 不做营销风展示
- 强调信息层级和结果可读性
- 保持后台业务结果页风格

---

## 8. 技术要求

1. 结果展示逻辑应放在结果页或必要的展示组件中
2. 如结果模块较多，可适度拆分为子组件
3. 不允许继续直接渲染原始对象字符串
4. 对数组、对象、分数、布尔值等字段应做合适格式化
5. 页面应便于后续历史记录页复用结果展示模块

## 10. 验收标准

2. 结果页能按模块展示诊断结果
3. 用户可快速看到总分、等级、亮点、问题与建议
4. 页面结构清晰、风格统一
5. `frontend/runtime/STATE.md` 已同步更新
