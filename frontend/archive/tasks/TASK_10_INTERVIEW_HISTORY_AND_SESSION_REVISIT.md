# TASK_10_INTERVIEW_HISTORY_AND_SESSION_REVISIT

## 任务背景

前端模拟面试会话页已经可用，用户可以进入模拟面试并完成基本问答流程。当前仍存在两个关键缺口：

1. 无法查看当前用户的模拟面试历史记录
2. 首页“最近模拟面试”模块尚未接入真实数据
3. 左侧“历史记录”页面当前只支持简历诊断历史，不支持模拟面试历史回访

后端已具备以下接口基础：

- POST /session/{sessionId}/end
- GET /session/{sessionId}
- GET /history

其中：
- `/history` 可返回当前用户的面试历史记录
- `/session/{sessionId}` 可返回指定会话详情及聊天记录

因此本任务先补齐“模拟面试历史记录与会话回访”链路，为后续“结束后评价报告”页面打基础。

---

## 任务目标

完成模拟面试历史记录相关前端能力，至少包括：

1. 首页“最近模拟面试”接入真实历史数据
2. “查看全部”进入模拟面试历史记录页
3. 新增或完善模拟面试历史页，展示当前用户的历史面试记录
4. 每条历史记录可进入对应 session 详情页
5. 与当前已完成的模拟面试会话页路由保持一致
6. 历史链路中的 sessionId 传递保持一致，不出现参数错乱

---

## 本任务范围

本任务聚焦以下内容：

- 模拟面试 history API 接入
- 首页最近模拟面试模块
- 模拟面试历史列表页
- 从历史记录回访会话详情
- 路由与菜单归属
- 空态、加载态、错误态基础处理

---

## 本任务不做的内容

本任务暂不包含：

1. 面试结束后的评价报告页
2. 复杂评分图表或分析模块
3. 面试历史高级筛选和分页优化
4. 语音回放、导出报告等扩展功能

---

## 已知后端接口

### 1. 结束面试
- `POST /session/{sessionId}/end`

### 2. 查询会话详情
- `GET /session/{sessionId}`

### 3. 查询当前用户面试历史
- `GET /history`

说明：
- 这些接口均依赖登录态
- 前端请求时必须带有效 token
- 会话详情接口可作为“查看历史会话内容”的基础数据源

---

## 实施要求

### 1. API 层接入
- 在前端 interview API 文件中补充：
  - 获取面试历史列表方法
  - 获取会话详情方法（如当前未统一封装）
  - 结束面试方法（如当前未统一封装）

### 2. 首页最近模拟面试模块
- 接入真实历史数据
- 展示最近若干条面试记录
- “查看全部”跳转到模拟面试历史页
- 空态文案要正确

### 3. 模拟面试历史页
- 新增或完善独立页面
- 至少展示：
  - sessionId（如不适合直接展示，可内部保留）
  - 面试岗位
  - 难度
  - 模式
  - 创建时间
  - 状态（如果后端有）
  - 查看会话按钮
- 空态、加载态、错误态需要可用

### 4. 历史回访链路
- 点击历史记录后进入对应 session 页面
- 使用真实 sessionId 跳转
- 刷新页面后仍可通过 sessionId 重新拉取详情
- 不要出现简历 taskId 类似的问题；sessionId 统一按字符串传递

### 5. 输出要求
完成后必须输出：
1. 新增和修改文件清单
2. 所有新增和修改文件完整内容
3. 首页最近模拟面试模块接入说明
4. 模拟面试历史页说明
5. session 回访链路说明
6. 更新后的 frontend/runtime/STATE.md 完整内容

---

## 完成标准

满足以下条件时，可认为本任务完成：

- 首页最近模拟面试显示真实数据或合理空态
- 可进入模拟面试历史页
- 历史页可展示当前用户面试记录
- 可从历史记录进入对应 session 详情页
- sessionId 传递正确，刷新后仍可加载
- runtime 状态文档已更新
