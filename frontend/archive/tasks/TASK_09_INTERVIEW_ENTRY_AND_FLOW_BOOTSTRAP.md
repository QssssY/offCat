# TASK_09_INTERVIEW_ENTRY_AND_FLOW_BOOTSTRAP

## 任务背景

前端“简历诊断”主链路已经完成并通过 TASK_08 联调验收，当前具备以下已完成能力：

- 前端工程初始化完成
- 用户登录与鉴权接入完成
- 首页与主布局完成
- 简历诊断入口完成
- 简历上传与结果页跳转链路完成
- taskId 精度问题已修复，历史链路统一按 string 传递
- 简历诊断结果页结构化展示完成
- 历史记录页完成
- 左侧导航激活态问题已修复
- TASK_08 验收通过，简历诊断链路阶段性完成

当前需要启动系统第二条核心业务线：“模拟面试”。

本任务用于建立模拟面试模块的前端最小可用骨架，为后续联调、流程完善和结果页建设打基础。

---

## 任务目标

完成模拟面试模块第一阶段前端建设，建立“入口可访问、页面可承载、路由可跳转、后续可联调”的最小可用链路。

本阶段完成后，前端应至少具备以下能力：

1. 用户可以从首页进入模拟面试模块
2. 系统存在独立的模拟面试入口页面
3. 页面具备基础骨架和信息组织结构
4. 页面预留模式选择 / 岗位信息 / 难度设置 / 开始面试等区域
5. 路由与菜单高亮逻辑正确
6. 为后续接入真实接口预留清晰的数据结构和交互边界

---

## 本阶段范围

本任务聚焦“模拟面试入口与流程骨架”，包括：

- 首页模拟面试入口联通
- 模拟面试入口页
- 路由配置接入
- 基础表单区域或模式选择区域
- 空态 / 占位态
- 与现有主布局、导航体系保持一致
- 为后续联调保留清晰扩展点

---

## 本阶段不做的内容

为避免范围失控，本任务明确不包含以下内容：

1. 不实现完整实时对话或语音链路
2. 不实现复杂面试过程状态机
3. 不实现完整的面试结果分析页
4. 不在本阶段引入复杂 WebSocket 或流式交互
5. 不做超出已有 UI 规范的大规模设计重构
6. 不擅自改动已完成的简历诊断主链路

---

## 实施要求

### 1. 后端能力梳理

在开始页面实现前，先梳理当前项目中是否已经存在模拟面试相关能力，包括但不限于：

- 模拟面试创建接口
- 模拟面试历史记录接口
- 模拟面试结果查询接口
- 岗位 / 难度 / 面试模式相关数据结构
- 后端已有任务文档中与模拟面试相关的约束

如果后端能力尚未完整具备，则本阶段优先完成前端骨架，不强行联调。

### 2. 页面与路由建设

新增或完善模拟面试入口页面，要求：

- 页面可通过首页“开始面试”进入
- 路由路径清晰，命名与现有前端风格一致
- 左侧菜单高亮逻辑正确
- 与主布局、顶部区域、内容区风格一致

### 3. 页面结构要求

页面至少包含以下结构区域：

- 页面标题与说明文案
- 岗位 / 方向选择区域（如后端能力允许）
- 难度选择区域（如后端能力允许）
- 面试模式说明区或占位说明区
- 开始面试按钮
- 暂不可用能力的提示或占位区

### 4. 交互要求

- 当后端未就绪时，不制造假联调成功效果
- 若暂时无法开始真实面试，应明确展示“待接入”或“即将支持”的占位态
- 若已有后端接口，则优先接入最小闭环
- 页面行为必须清晰，不允许出现点击后无反馈的状态

### 5. 工程一致性要求

- 保持现有 UI 风格规范
- 保持页面骨架和组件使用的一致性
- 不擅自变更现有目录结构
- 如新增接口文件、页面文件、类型文件，应与当前项目组织方式保持一致

## 完成标准

满足以下条件时，可认为 TASK_09 第一阶段完成：

- 首页可以进入模拟面试入口页
- 模拟面试页面已接入主路由
- 页面具备清晰可用的骨架结构
- 页面不会出现明显空白、跳转失效、导航高亮错误等问题
- 已明确区分本阶段已实现能力与待后续接入能力
- runtime 状态文档已同步更新
