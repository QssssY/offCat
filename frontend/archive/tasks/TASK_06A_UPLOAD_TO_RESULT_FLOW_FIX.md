# TASK 06A - 简历上传到结果页跳转链路修复

## 1. 任务目标

修复当前简历诊断上传页在提交成功后仍停留在上传页并持续显示“处理中”的问题，确保上传成功后能够正确结束上传页状态，并基于返回的 `taskId` 跳转到结果页，由结果页负责承接任务状态展示。

---

## 2. 问题背景

当前前端已开始建设简历诊断结果页，但实际测试中发现：

- 用户上传 PDF 后
- 页面仍停留在 `/resume/upload`
- 上传按钮持续显示“处理中...”
- 无法进入结果页
- 因此也无法测试简历诊断结果页逻辑

结合当前后端情况可知：

- 后端上传与异步任务处理链路已基本可用
- 后端已有任务详情查询接口 `/task/{taskId}`
- 前端当前问题更可能出现在上传成功后的状态收口与页面跳转逻辑

当前正确的业务流应为：

1. 用户在上传页提交 PDF
2. 上传接口成功返回任务标识
3. 前端结束上传页提交态
4. 前端跳转到结果页
5. 结果页根据 `taskId` 展示任务状态与结果内容

---

## 3. 本任务范围

本任务应完成以下内容：

1. 检查上传接口返回结构
2. 确认前端是否正确读取 `taskId`
3. 修复上传成功后的跳转逻辑
4. 修复上传页 loading 状态未正确结束的问题
5. 确保“处理中”状态由结果页承接，而不是停留在上传页
6. 保持与现有结果页路由结构一致
7. 更新前端状态记录

---

## 4. 本任务不包含内容

本任务不包含以下内容：

- 修改后端上传接口
- 重构结果页整体展示结构
- 新增历史记录页
- 重做首页
- 修改 RabbitMQ 或异步处理逻辑

---

## 5. 修复重点

### 5.1 上传接口返回读取

重点确认：

- 上传成功后后端实际返回结构是什么
- `taskId` 位于哪个字段
- 前端是否按真实字段正确读取

不允许前端猜字段。

### 5.2 跳转逻辑

重点确认：

- 上传成功后是否执行 `router.push`
- 路由目标是否为结果页
- 路由参数是否正确传入 `taskId`

### 5.3 loading 状态管理

重点确认：

- 提交中状态是否只用于上传请求阶段
- 请求结束后是否正确关闭上传页 loading
- 是否存在因为分支漏写导致按钮一直停留在处理中状态

### 5.4 状态职责分离

必须明确：

- 上传页只负责“发起任务”
- 结果页负责“承接任务状态与结果展示”
- 不允许上传页无限承担异步任务轮询职责

---

## 6. 目标行为

修复完成后，系统应满足以下行为：

1. 用户上传 PDF 时，上传按钮进入提交中状态
2. 上传成功后，前端可正确获取 `taskId`
3. 上传页结束提交态
4. 前端自动跳转到结果页
5. 结果页根据 `taskId` 展示任务处理中 / 已完成 / 失败状态
6. 用户不再卡在上传页无法继续测试

---

## 7. 技术要求

4. 状态管理应简洁明确
5. 使用当前已有 Vue Router 结构完成修复
