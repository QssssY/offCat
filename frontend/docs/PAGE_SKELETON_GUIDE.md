# 页面结构与骨架规范

## 1. 页面设计原则

页面优先回答三个问题：
1. 这是在管理什么对象？
2. 当前用户最常做什么操作？
3. 信息的主次关系是什么？

页面不是为了好看，而是为了操作。

## 2. 标准后台页面结构

推荐后台页面基础骨架如下：

1. 页面标题区
   - 页面标题
   - 简要说明（可选）
   - 核心操作按钮（右侧）

2. 筛选 / 查询区（如有）
   - 条件表单
   - 查询 / 重置按钮
   - 高级筛选可折叠

3. 主体内容区
   - 表格 / 列表 / 信息块
   - 数据是页面主角

4. 辅助区域
   - 分页
   - 批量操作
   - 状态说明

## 3. 列表页（表格页）骨架

列表页必须：
- 表格作为核心
- 操作列固定位置
- 操作不堆成按钮墙
- 批量操作有明确入口

禁止：
- 表格外套多层卡片
- 操作散落在各个角落

## 4. 表单页骨架

- 表单字段按业务逻辑分组
- 长表单必须拆分模块
- 提交 / 取消位置固定
- 必填字段明确标识

不允许：
- 所有字段平铺
- 重要字段和次要字段视觉一致

## 5. 详情页骨架

- 基本信息区
- 业务信息区
- 操作记录 / 状态信息区
- 操作按钮集中，不分散

## 6. 弹窗与抽屉使用规则

- 简单编辑：弹窗
- 信息量大 / 多步骤：页面
- 抽屉用于：
  - 快速查看
  - 不打断主流程的操作

## 7. 空状态 / 异常状态

空状态必须说明：
- 为什么是空的
- 用户下一步能做什么

禁止：
- 只放一个图 + “暂无数据”

## 8. 判断标准

如果一个页面：
- 去掉颜色后依然清晰
- 信息层级一眼能看懂
- 操作路径明确

👉 说明页面骨架是合格的。
