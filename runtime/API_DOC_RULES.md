# 接口文档生成规范

## 1. 适用范围
本规范仅适用于当前项目中“前端需要访问的 HTTP 接口”文档的编写与生成。

以下类型接口必须生成或更新接口文档：
- 前端页面直接调用的 REST 接口
- 前后端联调用的公开 HTTP 接口
- 需要明确请求参数、响应结构、鉴权方式的业务接口

以下内容不属于本规范强制文档范围：
- Service 层方法
- Mapper / Repository
- MQ 消费者
- 定时任务
- 内部工具类方法
- 非前端调用的内部接口

## 2. 输出格式
- 接口文档必须使用 Markdown 格式
- 每个任务对应一个独立接口文档文件
- 文件命名格式：
  - `TASK_02_AUTH_API.md`
  - `TASK_03_QUOTA_API.md`
  - `TASK_04_RESUME_API.md`
  - `TASK_05_INTERVIEW_API.md`

## 3. 存放位置
所有接口文档统一存放在：
- `docs/api/`

## 4. 文档语言
- 全部使用中文说明
- 路径、字段名、代码值保持原始技术命名
- 说明文字使用简洁中文

## 5. 每个接口必须包含的内容

### 5.1 接口标题
使用二级标题，格式：
- `## 1. 用户注册`
- `## 2. 用户登录`

### 5.2 基本信息
每个接口必须包含以下信息：
- 请求路径
- 请求方法
- 接口说明
- 是否需要鉴权

示例：

- 请求路径：`/api/auth/register`
- 请求方法：`POST`
- 接口说明：注册普通用户账号
- 是否鉴权：否

### 5.3 请求头
如果接口需要鉴权，必须增加请求头说明：

| 名称          | 是否必填 | 说明         |
| ------------- | -------- | ------------ |
| Authorization | 是       | Bearer Token |

如果不需要鉴权，可写：
- 无特殊请求头要求

### 5.4 请求参数
如果是 JSON Body，请使用表格说明：

| 字段名 | 类型 | 是否必填 | 说明 |
|---|---|---|---|

如果无请求参数，必须明确写：
- 无请求参数

### 5.5 路径参数
如接口包含路径参数，必须单独列出：

| 字段名 | 类型 | 是否必填 | 说明 |

### 5.6 查询参数
如接口包含 Query 参数，必须单独列出：

| 字段名 | 类型 | 是否必填 | 说明 |

### 5.7 示例请求
如果接口有请求体，必须提供 JSON 示例。
如果是 GET 请求无请求体，可不写 JSON，但要保留请求路径示例。

### 5.8 返回结果说明
必须说明统一返回结构，例如：
- `code`：业务状态码
- `message`：响应信息
- `data`：业务数据
- `timestamp`：响应时间

如果 `data` 为对象，建议补充字段说明。

### 5.9 示例响应
每个接口必须提供成功响应示例。
如有典型失败场景，建议补充失败响应示例。

## 6. 统一风格要求
1. 所有接口文档结构顺序必须一致
2. 所有请求参数说明统一使用表格
3. 所有示例 JSON 必须合法
4. 所有接口路径必须与实际 Controller 保持一致
5. 所有字段名必须与 DTO / VO / 返回体保持一致
6. 不允许只写路径不写说明
7. 不允许省略鉴权要求
8. 不允许省略成功响应示例

## 7. 与代码同步要求
- 本轮新增或修改了“前端需要访问的 HTTP 接口”时，必须同步生成或更新对应接口文档
- 如果前端需要访问的接口字段发生变化，文档必须同步变化
- 不允许代码与文档不一致

## 8. 文档生成触发条件
满足以下任一条件时，必须生成或更新接口文档：
1. 新增了前端需要调用的 HTTP 接口
2. 修改了前端接口的请求路径、请求方法、请求参数、响应结构或鉴权方式
3. 删除了前端原有依赖的接口
4. 调整了接口返回字段，可能影响前端联调

如果本轮仅修改后端内部实现逻辑，且未影响前端访问方式，则不强制更新接口文档。
