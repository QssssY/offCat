# 日志记录规范

## 1. 适用范围
本规范适用于当前项目所有后端代码中的日志记录。

## 2. 总体原则
1. 所有关键业务方法必须记录日志
2. 日志应有助于排查问题、定位链路、确认状态流转
3. 日志内容必须简洁、清晰、结构化
4. 不允许记录敏感明文信息，例如密码、完整 token、完整密钥

## 3. 必须加日志的位置

### 3.1 Controller 层
以下情况必须记录日志：
- 接收到重要业务请求时
- 请求处理成功时
- 参数校验失败或业务异常时（如有显式处理）
- 关键标识信息，如 userId、taskId、sessionId

### 3.2 Service 层
以下情况必须记录日志：
- 核心业务开始执行
- 核心业务执行完成
- 状态流转前后
- 关键分支判断
- 异常捕获处

### 3.3 MQ / 异步任务
以下情况必须记录日志：
- 消息入队
- 消息消费开始
- 消费成功
- 消费失败
- 状态更新
- 重试或降级处理

## 4. 推荐日志级别
- info：正常业务流程、关键链路节点
- warn：可恢复异常、参数异常、依赖不可用但可降级
- error：业务执行失败、系统异常、外部依赖异常

## 5. 日志内容要求
日志中建议包含：
- 模块名
- 方法名或动作名
- 关键业务标识（userId、taskId、sessionId）
- 处理结果
- 错误原因（异常场景）

## 6. 禁止事项
1. 不记录密码明文
2. 不记录完整 JWT
3. 不记录完整 API Key
4. 不输出无意义日志，如“进入方法”“执行成功”但没有业务上下文

## 7. 代码要求
1. 统一使用 Slf4j 日志
2. 日志变量统一命名为 `log`
3. 类级别使用日志注解或标准 Logger 定义
4. 新增代码默认必须包含必要日志
5. 已完成模块在补充任务中应补齐关键日志
