# BUGFIX 08 - 上传接口返回任务ID与真实任务ID不一致修复

## 1. 修复目标

修复当前简历上传接口返回给前端的 taskId 与后端真实创建、处理、查询使用的 taskId 不一致的问题，确保前端拿到的 taskId 就是后端任务链路中唯一真实可查询的任务标识。

---

## 2. 问题背景

当前前端上传简历后，上传接口返回成功结果，例如：

- `code: 200`
- `message: "简历诊断任务已提交"`
- `data: 2039728612646490000`

但当前前端使用该值查询任务详情时，后端返回：

- `code: 500`
- `message: "任务不存在"`

与此同时，后端控制台日志显示异步任务处理成功的 taskId 为：

- `2039728612646490114`

这说明：

- 上传接口返回给前端的 ID
- 与后端异步链路真实使用的任务 ID

并不是同一个值。

因此，当前前端查不到任务并不是因为页面代码错误，而是因为后端返回了错误或不一致的任务标识。

---

## 3. 本修复范围

本修复应完成以下内容：

1. 明确上传接口当前返回值来源
2. 明确真实任务记录的 taskId 生成位置
3. 检查是否存在两次生成 ID、返回错误字段、旧逻辑残留等问题
4. 修复上传接口返回值，使其与真实任务记录主键一致
5. 验证前端上传成功后使用返回值即可查询任务详情
6. 保持现有异步任务链路继续可用

---

## 4. 不在本次修复范围内的内容

本次修复不包含：

- 修改前端页面结构
- 修改结果页 UI
- 重构 RabbitMQ 链路
- 开发历史记录页
- 改造整个 ID 生成策略

---

## 5. 必须排查的重点

### 5.1 上传接口返回值来源

必须明确：

- Controller 返回的 `data` 是从哪里来的
- 当前返回的值对应哪个对象
- 它是否真的是任务表主键

### 5.2 任务ID生成链路

必须明确：

- 真实任务记录的 ID 在哪里生成
- 是否在上传阶段与任务创建阶段分别生成了不同 ID
- 是否存在旧值被提前返回给前端

### 5.3 数据落库与MQ链路

必须明确：

- RabbitMQ 消费者处理的是哪个 taskId
- 任务状态更新的是哪个 taskId
- 数据库任务表中保存的是哪个 taskId
- 是否与上传接口响应值一致

### 5.4 查询接口一致性

必须明确：

- `/task/{taskId}` 查询的 taskId 是否就是任务表主键
- 查询接口与上传接口是否以同一个 taskId 语义工作

---

## 6. 修复原则

1. 前端拿到的 taskId 必须是后端任务链路中唯一真实可查询的 taskId。
2. 不允许继续返回中间对象 ID、错误字段或旧逻辑值。
3. 若当前存在两次生成 ID，应统一为单一任务标识。
4. 修复以最小改动原则为主。
5. 不修改前端代码。

---

## 7. 验收标准

满足以下条件可视为修复完成：

1. 上传接口返回的 taskId 与后端任务表中的 taskId 一致
2. 上传接口返回的 taskId 与 MQ 消费日志中的 taskId 一致
3. 前端使用返回的 taskId 查询任务详情时不再出现“任务不存在”
4. 异步任务处理链路保持正常
5. 无新增明显副作用

---

## 8. 验证要求

修复后至少验证以下场景：

1. 上传一个 PDF
2. 记录上传接口返回的 taskId
3. 查看后端日志中真实处理的 taskId
4. 确认两者完全一致
5. 使用该 taskId 调用任务详情接口
6. 确认可正常查询到任务状态与详情

---

## 9. 输出要求

完成本修复后，应输出：

1. 根因分析结论
2. 上传返回值与真实任务ID不一致的具体原因
3. 修改的后端文件清单
4. 逐文件完整修改内容
5. 修复后的 taskId 生成与返回逻辑说明
6. 验证步骤与结果
7. 是否需要同步更新状态或文档

---

## 10. 备注

本修复属于简历诊断上传链路中的关键一致性问题修复。

只有修复上传返回值与真实任务ID的一致性，前端结果页查询链路才能真正跑通。
