# TASK 10 - 用户额度兜底初始化插入参数修复

## 1. 任务目标

修复用户额度兜底初始化逻辑在插入 `user_quota` 记录时缺少 `user_id` 参数的问题，确保当系统检测到用户额度记录不存在时，能够正确为当前用户创建额度记录，而不会触发数据库非空字段插入异常。

---

## 2. 任务背景

在 TASK_09 中，后端已为用户额度增加“记录不存在时自动初始化”的兜底逻辑。

当前实际测试中发现：

- 新用户登录后发起简历诊断
- 系统检测不到 quota 记录
- 自动执行 quota 初始化逻辑
- 插入数据库时报错：
  `Field 'user_id' doesn't have a default value`

异常定位信息显示：

- 错误发生在 `UserQuotaMapper.insert`
- 属于数据库插入阶段参数缺失
- 说明当前初始化对象在插入时未正确写入 `user_id`

这说明 TASK_09 的思路是正确的，但实现中缺失了关键关联字段赋值。

---

## 3. 本任务范围

本任务应完成以下内容：

1. 定位 quota 自动初始化逻辑中的插入参数构造代码
2. 确认当前用户 `userId` 的获取来源
3. 确认 `UserQuota` 插入对象在落库前已正确设置 `userId`
4. 修复所有相关兜底初始化入口
5. 验证简历诊断和模拟面试两条链路在 quota 不存在时都能正常初始化
6. 确保修复后不会影响已有 quota 用户
7. 更新必要状态与交付记录

---

## 4. 本任务不包含内容

本任务不包含以下内容：

- 修改前端上传逻辑
- 修改数据库表结构以绕过问题
- 为 `user_id` 设置数据库默认值
- 重构整个 quota 模块
- 修改 token 认证逻辑
- 修改登录注册流程

---

## 5. 排查重点

### 5.1 初始化方法签名与调用链

重点检查：

- quota 初始化方法是否显式接收 `userId`
- 调用处是否把当前用户 ID 传入
- 是否存在从认证上下文获取用户 ID 失败的情况
- 是否存在只初始化默认次数、未设置用户关联字段的情况

### 5.2 当前用户 ID 获取方式

重点检查：

- 当前用户 ID 是从哪里获取的
- 是从 token 解析、登录上下文、session 还是安全工具类中读取
- 获取逻辑是否在简历诊断和模拟面试两条链路中一致
- userId 是否可能为 null

### 5.3 UserQuota 对象构造逻辑

重点检查：

- 在执行 `insert` 前，`UserQuota` 对象是否已设置：
  - `userId`
  - 默认简历诊断次数
  - 默认模拟面试次数
  - 其他必要字段
- 是否存在字段命名映射错误或 set 方法遗漏

### 5.4 多入口一致性

重点检查：

- `checkResumeQuota()`
- `checkInterviewQuota()`
- `deductResumeQuota()`
- `deductInterviewQuota()`

若这些方法都可能触发兜底初始化，则必须全部修正一致。

---

## 6. 修复目标

修复完成后，系统应满足以下行为：

1. 当用户 quota 记录不存在时，系统可自动为当前用户创建 quota 记录
2. 创建 quota 记录时，`user_id` 必须正确写入
3. 新用户首次使用简历诊断功能时，不再因 quota 初始化插入失败而报错
4. 新用户首次使用模拟面试功能时，也应具备相同兜底能力
5. 已存在 quota 记录的用户不受影响

---

## 7. 实施要求

1. 必须从业务代码层修复，不允许通过修改数据库字段默认值规避问题。
2. quota 初始化逻辑必须显式绑定当前用户。
3. 如当前初始化方法参数设计不合理，可进行最小范围重构。
4. 若当前用户 ID 获取存在公共工具方法，应优先复用，避免重复实现。
5. 修复后建议在关键位置增加必要日志，便于后续排查初始化问题。

---

## 8. 验收标准

满足以下条件可视为本任务完成：

1. quota 记录不存在时，系统可成功自动初始化
2. 插入 `user_quota` 时不再出现 `user_id` 缺失错误
3. 新用户首次进入简历诊断功能可正常通过额度检查
4. 新用户首次进入模拟面试功能也可正常通过额度检查
5. 不影响已有用户已有 quota 数据
6. 修复逻辑清晰，调用链明确，可解释

---

## 9. 验证要求

修复后至少验证以下场景：

1. 使用一个没有 quota 记录的新用户账号登录
2. 发起简历诊断请求
3. 检查数据库中是否成功生成该用户的 quota 记录
4. 确认 `user_quota.user_id` 正确写入
5. 如适用，验证模拟面试入口也可正常初始化 quota
6. 再次发起请求，确认已有 quota 场景正常运行

---

## 10. 输出要求

完成本任务后，应输出：

1. 问题原因分析
2. 修改的后端文件清单
3. 逐文件完整修改内容
4. quota 初始化修复说明
5. 当前用户 ID 获取与传递方式说明
6. 验证步骤与验证结果
7. 需要同步更新的状态或文档

---

## 11. 备注

本任务属于 TASK_09 的落地修正任务。

TASK_09 解决的是“新用户 quota 不存在时要自动初始化”的策略问题；
本任务解决的是“初始化落库时必须正确绑定 user_id”的实现问题。

只有本任务完成后，兜底初始化策略才能真正稳定生效。
